一句提示词，是怎么变成一张图的？

[ 01 · 起点 ]

一句提示词，中间发生了什么

在 ComfyUI 里敲一句 a sunset over mountains, calm lake，点 Queue，几秒后一张 512×512 的图出现在屏幕上。这几秒钟里，到底发生了什么？

先把这件事的难度摆具体。一张 512×512 的图由 786,432 个数字组成——每个像素 3 个通道（R/G/B），每个通道取值 0~255。这些数字能摆出的组合数量，量级是 10^1,893,917；而这堆组合里「看起来像一张自然的日落风景」的那一小撮，在这个天文数字般的空间里比一粒尘埃还小。要一个网络凭一句话直接猜中这一撮、一次到位，是不现实的——这正是全文要解决的问题。

关键心智模型 生成一张图，不是「从零开始画对」，而是从这个巨大的候选空间里，一步步排除不像的可能，直到落进那一小撮里。这是「减法」而非「加法」的由来——第 03 节会把这句话钉死成一个可验证的公式。

先划清这篇的范围：讲的是文生图（txt2img）的主干——一句话进去，一张图出来，中间网络怎么把噪声变成图像。模型是怎么训出来的、LoRA / ControlNet 这类往流程里插东西的扩展、拿一张已有图接着改的图生图，都不在这篇里。先把主干走通，边界自然清楚。

这几秒钟不是一个黑盒，而是一条流水线。ComfyUI 把它明明白白画成了几个方块——点 Queue 时，数据真的按这个顺序从一个方块流到下一个。下面是它的全景图，点开任意节点看它具体负责什么；后面每一节，都对应其中一个方块。

[ 02 · 取舍 ]

为什么不能一步生成

上一节留了一个问题：候选空间这么大，为什么不干脆训练一个网络，输入一句话直接吐出图像？

一步到位，等于要网络学会一个从「随机数」到「自然图像」的映射——这个映射极度复杂，训练信号也很难给：你没法直接告诉网络「这张图错在哪、该往哪个方向改一点」。（GAN 走的是另一条路，靠一个判别器打分当训练信号，代价是训练不稳、容易模式坍缩——这里只作一句对照，不展开。）

扩散模型的立意 把一个做不到的难题，换成几十个几乎一样、都很容易的小题。每一步只需要回答「这张有点糊的图上，噪声大概长什么样」——这个问题简单到可以用海量数据直接监督。

训练样本怎么造，答案很朴素：拿一张真图 x₀，随机挑一个时间步 t，按 x_t = √ᾱ_t·x₀ + √(1−ᾱ_t)·ε 把它和一份随机噪声 ε 混合，网络输入 x_t 和 t，标签就是 ε 本身。这一步不需要人工标注——训练数据近乎无限（网上任意一张图都能造），标签是免费的（噪声自己加的，天然已知）。这正是扩散模型能被训起来的关键。

代价 把难题拆细的代价是要跑很多次。一次生成 = 网络前向 N 次（还要乘 CFG 的两遍，正负提示词各算一次），这就是文生图比一次分类慢好几个数量级的原因。这个 N，也就是 steps，会在第 10、11 节变成一个你能亲手调的参数。

本节收束 把「一步蒙对」换成「学会擦掉一层薄噪声、然后重复」——这正是下一节要钉死的第一因。
[ 03 · 第一因 ]

学会「减掉一点噪声」，然后重复

上一节说清楚了为什么要把生成拆成几十步小任务。这一节回答更根本的问题：模型每一步到底在学什么。答案只有一句话，但后面每一节都在围着它转。

第一因模型学会的只有一个动作：给它一张带噪声的图和一个噪声水平 t，它输出「我认为这上面的噪声长什么样」。生成，就是从一团纯噪声出发，把这一个动作重复几十次，每次减掉预测出来的那一点点噪声。它不是在画，是在擦。

前向加噪与反向去噪，是同一件事的两个方向

训练时不需要真的把图一步步弄脏。有一条公式能直接把干净图 x0 一步跳到任意噪声水平 t，这也是训练能高效造样本的原因——不用真的模拟 t 次加噪。生成时反过来，从纯噪声 xT 出发，只能老老实实一步步走回来，因为每一步要用的是网络刚刚给出的那个预测，无法预先知道。

一个记号上的提醒这里写的 x 是「被加噪的那个东西」。在 Stable Diffusion 里，它不是像素图，而是潜空间里的张量，通常记作 z。整套加噪去噪的数学一字不改，只是舞台从 512×512×3 换成了小得多的 64×64×4——下一节就讲为什么要换。本节的插图为了直观仍画在像素上，读的时候心里换成 z 即可。

预测出噪声之后，为什么不一次减完

既然网络已经告诉你「噪声长这样」，把它一次全减掉不就完事了？这一步确实可以做，而且有个名字：把 ε̂ 代回前向公式反解，就得到一个一步到位的成品猜测

// 一次全减完，直接得到「它以为的干净图」
x̂₀ = ( x_t − √(1−ᾱ_t) · ε̂ ) / √ᾱ_t

问题在于：噪声很大的时候，这个 x̂₀ 必然是模糊的。网络此刻只能看出「大概是个日落、山在左边」，看不出任何细节，所以它反解出来的成品猜测也就只有这么多信息。不过这一点页面上的演示替不了你验证：首屏那个滑块展示的是「画面被噪声盖住多少」，而 x̂₀ 模糊是另一回事——它是网络在信息不足时给出的重建上限。两者方向一致，但不是同一件事。

第一因的下半句所以真实的做法不是一次减完，而是：算出这个成品猜测，然后只朝它走一小步，再用新的位置重新问一遍网络。走一小步之后噪声少了一点，网络看得清一点，下一次的猜测就更准一点。「多步」的收益全部来自这里——不是把噪声分几次减，而是让网络有机会反复修正自己的判断。这一小步要迈多远、怎么迈，被 KSampler 拆成了两个互相独立的决定——噪声表决定这一步跨越多大的噪声落差，采样器决定在这段落差里怎么走。第 10 节把这两件事分开讲。

为什么预测噪声，而不是直接预测图

直觉是这样的：噪声 ε 的分布是已知且固定的——标准正态，均值为 0，各分量独立同分布。而「干净图长什么样」的分布，正是模型要学的全部难点所在。把训练目标换成噪声，等于把一个开放性的生成问题，转化成了一个有固定基准的残差回归问题：网络不用凭空猜图，只需要猜「这张脏图比干净图多出来的那部分」，这个目标更规整，也更容易训。

诚实说明业内也有直接预测 x0、或预测两者组合 v 的参数化方式，它们和 ε-prediction 在数学上可以互相换算，选哪种主要影响训练稳定性。这里只讲最常见、最容易讲清楚的 ε-prediction，后面各节的公式也都基于它。

noise schedule：ᾱt 这张表怎么定噪声进度

公式里的 ᾱt 是一张查表得到的数，t 从 0 到 T 依次取值，决定每一步该混入多少噪声。原始 DDPM 用的是最直白的办法：让每步新增的噪声量 β 线性增长。后来有人发现这张表有个问题——不用听我说，下面这个对照台可以亲眼验证。

误区「去噪就是把图变清晰，像 Photoshop 的降噪滤镜」——不对。滤镜是在一张已经存在的图上做平滑，抹掉的是画面里本来就有的噪点；这里发生的事情性质不同：从一团什么都没有的纯噪声出发，一步步减出一张原本并不存在的图。每一步该减掉什么，由提示词决定，这是第 07、08 节的内容。
本节收束模型在学什么、生成在做什么，说清楚了。但这两条公式没规定这几十步的计算要在哪个空间里跑——下一节看为什么不在原始像素上做，而是先把图压进一个小得多的潜空间。
[ 04 · 潜空间 ]

为什么不在像素上做，而在潜空间里做

上一节讲清楚了每一步在做什么；这一节讲清楚这几十步到底在哪算的，以及 Stable Diffusion 名字里的「Latent」从哪来。

把第 03 节的公式在 512×512×3 的像素网格上跑一遍并不便宜，而生成要重复几十步、每步都要完整过一遍 U-Net（去噪主干网络）。Stable Diffusion 的做法是不在像素上做这件事：先用 VAE 的编码器把图压成一个小得多的表示，全部去噪都在这个小表示里进行，最后再用 VAE 的解码器把结果变回像素。这个小得多的表示，就是「潜空间」（latent space）——模型名字里 Latent 的由来，也是它能在消费级显卡上跑起来的直接原因。

换算成数字更直观：512×512×3 是 786,432 个数，64×64×4 只有 16,384 个数，两者相差 48 倍——空间边长压缩了 8 倍（512÷64），通道数从 3 变成 4。下面这个计算器把这笔账摊开，换成别的分辨率也能自己验证：只要宽高都能被 8 整除，压缩倍数基本不变，这也是 SDXL 把默认分辨率提到 1024×1024 之后，latent 依旧只有 128×128×4 的原因。

压缩率计算器
 
空间元素个数相对像素空间

这个倍数算的是「元素个数」，不是字节数。像素通常是每通道 1 字节的 uint8，而 latent 是浮点（常见 fp16，每个数 2 字节）。按字节算，同一组配置下的压缩比只有元素比的一半左右。想拿它去估显存的话，记得先换算口径。

澄清latent 的那 4 个通道不是 RGBA，也不对应任何人类能命名的东西。网上常见的「latent 预览图」，是把这 4 个通道用一个固定矩阵近似映射到 RGB 得到的近似可视化，并不是 latent 本身真实的样子——这里保守地只说到这一步。

压缩到这么小，为什么还能还原

自然图像里有大量冗余，VAE 学到的是一个「够用」的压缩表示，不是无损压缩。代价也很实在：非常细的纹理、密集的小字、规则的网格，最容易在这一步丢掉信息，第 12 节还会再碰到这个问题。

右边只是尺度示意——把左边这张图按 8 倍下采样后放大显示，帮助感受「信息被压到多小的格子里」。真实的 latent 不是把图缩小得到的，也不长这样：64×64 里的每个位置编码的是原图对应 8×8 区块的语义与结构信息，不是那 64 个像素的平均颜色。

误区「潜空间就是缩略图」——不是。它不是把图缩小，而是换了一套表示；上面那张右侧示意用的像素平均只是为了让你看清尺度差了多少，真正的 VAE 编码器学到的是语义级的压缩，不是简单缩放。

[ 05 · 总览 ]

六个节点，一条数据流

ComfyUI 的价值就在这里：它把前两节讲的机制，明明白白画成了一张有向图。别的界面把整条流水线折进一张参数表单里，这里你能直接看见数据在节点之间怎么流动。

整张图只认六种「接口」。每一条连线都带着类型，类型决定了它能插到哪个输入口——两个节点看起来再不同，只要接口类型对得上就能接起来：

六种数据类型
  • MODEL　U-Net 权重，负责「预测噪声」这一个动作。
  • CLIP　文本编码器本身，把字符串变成向量。
  • CONDITIONING　编码后的提示词，是喂给 KSampler 的「指引」。
  • LATENT　潜空间里那团数据，是被反复擦拭的画布。
  • VAE　编解码器，负责潜空间与像素之间的转换。
  • IMAGE　最终落盘的像素图。

这也是 ComfyUI 界面上一个很直观的校验：拖一条连线出去，颜色对不上的插槽根本接不进去——连线的颜色本身就是一层类型检查，不需要额外看文档才知道两个节点能不能接在一起。

六个节点串成一条链，先各自记一句话，展开都留给后面几节：Load Checkpoint 一次性掏出 MODEL、CLIP、VAE 三样东西；CLIP Text Encode 正负各一路，把话变成 CONDITIONING；Empty Latent Image 准备一块指定尺寸的空白潜空间画布；KSampler 拿到 MODEL、两路 CONDITIONING 和 LATENT，在这里反复去噪；VAE Decode 把 LATENT 还原成像素；Save Image 落盘。

误区 「提示词直接进了 KSampler」——不对。KSampler 拿到的从来不是文字，而是已经编码好的 CONDITIONING 张量，它并不知道原始提示词长什么样。改一句提示词，改的其实是 CLIP Text Encode 那一步的输出，KSampler 只是被动接收这个变化。

[ 06 · 节点 · MODEL ]

Load Checkpoint 装了什么

一个 .safetensors 文件为什么能一次输出三种类型？因为它不是一块整体权重，而是打包了三套彼此独立的东西：U-Net（去噪主干）、文本编码器 CLIP、VAE（编解码器）。ComfyUI 的三个输出口，就是把这三样原样拆出来。

打包不等于焊死。这三样都可以被单独换掉：外挂一个单独的 VAE（第 12 节讲为什么要这么做），或者换一个文本编码器，都是成立的操作。把 checkpoint 理解成「一个打包」而不是「一个不可分的整体」，是很多进阶玩法的基础。

文件后缀也值得说一句：.safetensors 是纯张量容器，加载时不执行任何代码；.ckpt 是 Python pickle，反序列化时可能执行文件里携带的任意代码。社区已经普遍转向前者。

U-Net 在做什么

三者里，U-Net 承担的是「预测噪声」这个动作。它的结构大致是一条「下采样—上采样加跳跃连接」的路径：输入是带噪的 latent 加上时间步 t，逐级下采样进入中间层，再逐级上采样，期间通过跳连把早期的细节直接搭回对应的上采样层。它的输出和输入形状完全一致——都是同一块 [1, 4, 64, 64] 的 latent（对应第 04 节算过的 64×64×4）。正因为形状相同，输出的噪声估计才能直接从输入里逐点减掉。提示词并不是拼接进输入的，而是在下采样、中间层、上采样的每一级里通过 cross-attention 注入（第 07、08 节展开）。

形状先收缩、后还原，输入输出维度完全一致。橙色点是 cross-attention 的注入位置（见第 08 节）；灰色虚线弧是跳连，把下采样阶段的细节直接搭回对应的上采样层。

补充同一个 checkpoint 里，U-Net、CLIP、VAE 三者的规格是配套设计的——latent 通道数、原生分辨率、文本编码器的规格，很大程度上由底模版本决定。拿到一个陌生的 workflow，第一件事最好是看它用的是什么底模，很多参数选择其实是被它决定的，不是随手调的。
误区「底模决定画风，采样器决定质量」——前半句大致成立，后半句不准。采样器主要影响的是同样步数下的收敛程度，不是画风的来源；换一个采样器不会把一个写实底模变成动漫风格（采样器的作用见第 10 节）。
本节收束MODEL、CLIP、VAE，三样东西都拿到了。下一节先看 CLIP 这一路——你敲的那句话，是怎么变成模型能用的东西的。
[ 07 · 节点 · CLIP ]

你敲的那句话，是怎么变成模型能用的东西的

提示词不是整句塞给模型的。它先被切碎成 token，再逐个编码成向量，最后拼成一份 CONDITIONING——这中间每一步都有硬性限制，摸清它们，很多「提示词没用」的疑惑会自己消失。

第一步是分词，而且不是按单词切：常见词通常整词就是一个 token，生僻词、拼错的词、生造的名字往往会被拆成好几个模型从没见过的碎片组合。这正是生造词、拼写错误、罕见专有名词效果差的直接原因——不是模型「不认识」，是它被拆成了训练时几乎没见过的碎片拼法。

第二个限制更硬：文本编码器一次只认 77 个位置，其中第 0 位是起始标记、第 76 位是结束标记，真正能塞内容的只有中间 75 个。超出这 75 个的部分会被直接砍掉——是彻底没有进入模型，不是权重变低一点。这是提示词写得太长时最常见的失效原因。

补充ComfyUI 等实现会把超长提示词切成几段分别编码再拼接，绕开这条 75 的限制，但代价是段与段之间的注意力关系会被打断。

77 个位置各自被编码成一个向量（SD1.x 常见是 768 维，不同版本规格不同），拼起来是一个 77 × 768 的张量，这就是 CONDITIONING。关键是：送进 U-Net 的不是「整句话压成的一个向量」，而是这 77 个位置各自向量组成的序列；U-Net 通过 cross-attention 在每一层去「查」这个序列，所以提示词不同部分能在不同层、不同位置发挥不同作用。

(word:1.3) 这类权重语法，改的是对应 token 的 embedding 数值本身——按比例放大或缩小它，并不是让模型「更用心看」这个词。调得过大会让这个向量偏出训练时见过的分布范围，效果反而崩坏。

误区「提示词越长越好」——超过 75 个内容 token 的部分会被截断或需要另起一段编码，而且词越多，每个词分到的相对影响就越稀薄。「堆一堆 masterpiece, best quality 一定更好」——这类标签只有在训练数据里确实带过对应标注时才起作用，换一个底模效果可能天差地别，切勿默认有效。
本节收束提示词已经变成一份 77×768 的 CONDITIONING 张量。下一节看它具体怎么被用起来——正负提示词各跑一遍，再按 CFG 合成出这一步该走的方向。
[ 08 · 参数 · CFG ]

正负提示词与 CFG：模型每一步其实跑两遍

上一节那份 77×768 的 CONDITIONING 已经躺在 KSampler 的输入口上了，但模型并不会直接「照着它画」。它真正被用起来的方式，是让模型每一步跑两遍——正负各一遍，再按一条公式合成。这条公式就是 CFG（Classifier-Free Guidance），也是整条流水线里最容易被想歪的参数——它不是提示词的权重，而是决定每一步噪声预测怎么合成的公式。

先说负面提示词为什么存在。每一步，模型会跑两遍：一遍以正面提示词为条件，得到 ε_cond；一遍以负面提示词为条件（不写负面提示词时就是空文本），得到 ε_uncond。负面提示词从来不是「从画面里抠掉什么」，它真正改变的是 ε_uncond 这个基准预测。

ε = ε_uncond + scale × (ε_cond − ε_uncond)

ε_cond − ε_uncond 是「提示词指向的方向」，scale 是沿这个方向放大多少倍。scale = 1 时退化成只用 ε_cond，等于没有引导；scale = 0 时完全按 ε_uncond 走，提示词形同虚设。scale 越大，不是越「听话」，是这一步的更新量越「极端」。请把「极端」和「听话」这两件事分清楚。

调高 CFG 会发生什么放大倍数越大，每一步的更新量就越大，越容易冲出模型训练时见过的数据分布——表现出来就是过饱和、对比度爆炸、边缘发硬、细节焦掉。所以一张图看起来「烧焦了」，第一嫌疑永远是 CFG 太高，而不是模型不够听话。开启 CFG 意味着每步要跑两遍网络，单步耗时也因此约翻倍。

补充负面提示词写空也完全合法，此时 ε_uncond 就是空文本条件下的预测。很多人往负面里堆一长串词，但负面提示词同样占用那 77 个槽位，同样受第 07 节讲的截断规则约束。
误区「CFG 就是提示词权重」——不是，权重语法（(word:1.3)）改的是 token 的 embedding，CFG 改的是每一步噪声预测的合成方式，两者作用在完全不同的地方。「负面提示词能把画面里的东西删掉」——它只是换了一个 ε_uncond，从而改变了 ε_cond − ε_uncond 这个方向，它影响的是方向，不是对着画面做减法删元素。
本节收束提示词已经变成了「每一步该往哪走」的方向。下一节看这条路的起点——那块空白画布，以及决定它长什么样的 seed。
[ 09 · 节点 · LATENT ]

空白画布与 seed：为什么同样的提示词能出完全不同的图

Empty Latent Image 这个节点其实什么都没算——它只是按你给的宽高，准备一块空白的张量。真正决定这张图从哪里出发的，是紧跟着它工作的那颗 seed。

打开 Empty Latent Image 的属性面板，能调的只有 width、height、batch_size 三项，没有任何看起来「有内容」的参数。它做的事情很朴素：按 [1, 4, H/8, W/8] 的形状开一块 LATENT 张量，此刻里面全是 0——不是噪声，不是构图，什么都不是。第 04 节讲过的 8 倍下采样，就是在这里落地的：宽高必须除得尽 8，因为 VAE 在潜空间与像素之间换算用的正是 8 倍这个比例（文生图这一路只走解码方向：64×64 → 512×512）。

宽高 → LATENT 形状计算器

真正带来随机性的不是这个节点，而是 KSampler 启动时做的一件事：它会用 seed 生成一团随机噪声，填进这块刚开出来的空白画布——生成的起点，是这团噪声，不是空白本身。seed 决定了这团初始噪声里的每一个数值，而这团初始噪声取到的具体数值，会一路影响到最终图像的构图走向。

seed → 初始噪声

这是页面自己的伪随机数发生器按这颗 seed 生成的一片高斯噪声，按 RGB 三通道画出来示意——真实的初始噪声是 4 通道的潜空间张量，没法直接看（见第 04 节的澄清）。要点不在它长什么样，而在于：同一颗 seed 永远给出同一片数——KSampler 接下来所有的工作，都是把这团东西一点点擦掉。

尺寸怎么选

宽高必须是 8 的倍数，这是硬性要求，不是建议，上面的计算器会直接把非法尺寸拦下来。另外一条经验性的提醒：偏离底模原生训练时常见的分辨率太远，容易出现构图上的问题（比如人物多出一颗头或一条肢体），因为模型在那个尺寸组合上没见过足够多的样本——具体该定多少并没有一个通用答案，遇到这类问题时不妨先怀疑是不是尺寸选得过于极端。

误区 「seed 是个玄学幸运数字」——它只是随机数发生器的起点，本身无所谓好坏。所谓「好 seed」，只有在其余参数完全不变的前提下才成立；换一句提示词、换一个尺寸，同一颗 seed 给出的构图就完全是另一回事了，「好运」并不会跟着 seed 一起迁移。
误区 「batch 里第二张图的 seed 就是 seed+1」——不同实现的具体处理方式并不一致，不要把这条当成能依赖的规律。
本节收束 画布本身是空的；真正的起点是那团由 seed 决定的初始噪声，也是全链路唯一能让结果复现的东西。下一节看 KSampler 怎么把这团噪声一步步变成图——先看它给每一步安排的噪声水平表，再看它每一步具体怎么走。
[ 10 · 节点 · 采样 ]

KSampler：sigma 表决定每步跨多远，采样器决定怎么走

去噪这条路怎么走，其实被拆成两个互相独立的决定：路标怎么放，和两个路标之间怎么走。前者叫 scheduler，后者叫 sampler——ComfyUI 把它们做成两个下拉框，正是因为它们管的是两件不同的事。

scheduler：噪声表怎么放路标

KSampler 拿到的步数 N，并不是把 t 从 999 均匀切成 N 份。scheduler 决定这 N 步具体落在哪些噪声水平上，而且步与步之间通常不是均匀的——噪声大的阶段跨得大，接近干净的阶段跨得小。第 03 节出现过的线性表和余弦表，正是两种真实存在的噪声表，这里直接拿它们的 ᾱ 换算出噪声水平 σ 来对比：

sampler：两点之间怎么走

回到第 03 节那个动作：网络在当前位置给出一份噪声预测，反解出一个成品猜测 x̂₀，真正落地的只是朝它迈的那一小步。sampler 决定的就是这一步怎么迈——一阶方法只信当前这一次预测给的方向；高阶方法会在同一步里再问网络一次，用两次预测折中出一个更准的方向。所谓「不同的数值解法」，差别全在这里：本质上是在解同一条微分方程，不同 sampler 只是不同的数值解法：

  • 一阶方法（Euler 一类）：每步只用当前点的斜率，简单，每步只需一次网络前向。
  • 高阶方法（Heun、DPM++ 的二阶变体一类）：每步多算一次或几次前向来修正方向，单步更准，但单步也更贵；同样的步数下，走的路线通常比一阶方法更贴近真实解——注意这只是「同样步数下收敛程度不同」，具体该走多少步是下一节的话题。

比记住这些名字更实用的一条区分，是名字里带不带 a 或 sde 的那一类——ancestral / SDE 采样器：它们每一步都会额外注入一点新噪声。后果很关键：它们不会收敛到一个固定结果，步数一变，输出就跟着变，哪怕其余参数完全相同；而 ddim、名字带 _2m 这类确定性采样器，步数增加时结果会逐渐趋于稳定。下面用页面上的加噪公式模拟这个差异：

职责边界 同一个 sampler 配不同 scheduler，是不同的组合；同一个 scheduler 换一个 sampler，也是不同的组合。很多人把「用了 DPM++ 2M」和「用了 Karras」混着当成一回事去描述，其实这是两个独立的下拉框，各管各的——一个决定路标怎么放，一个决定怎么走到下一个路标，二者可以任意搭配。
本节收束 路标怎么放、怎么走，现在都清楚了。下一节回答那个最常被问的问题——到底该走多少步。
[ 11 · 参数 · STEPS ]

steps 该走多少步，denoise 又是什么

KSampler 面板上最显眼的两个数字。多数人的直觉是「steps 越大越精细，denoise 是去噪力度」——这两句话都只对了一半，甚至第二句基本是错的。

steps 决定的是把从纯噪声到成品这条路径切成多少段来走。它不是画质档位，而是数值积分的精度：把一条连续的曲线拆成折线段去逼近，段数越多，每一步跨得越小，离散误差越小，走出来的折线越贴近真实曲线。这也是为什么 03 节说的「预测噪声、减掉，重复几十次」要重复很多次而不是一次——一步跨太远，误差就大。

但误差下降得越来越慢 从 4 步到 8 步，折线明显更贴合；从 16 步到 32 步，肉眼已经很难分辨。误差不是匀速下降的，而是越往后收益越薄——到某一点之后，多给的步数带来的画面变化，比采样过程本身的随机性还小。「steps 越多越好」不成立，超过这个点纯粹是在多等而已。
模拟 离散化误差随步数的变化

四格用加噪公式 x=√ᾱ·x₀+√(1−ᾱ)·ε 反过来演示：步数越多，对应保留的「残留噪声」越少。这不是真的跑一遍采样，只是借同一条公式，把「步数增多→离散误差变小→收益递减」这件事画出来给你看形状。

这个收敛点在哪，还得回到 10 节的结论去看采样器是哪一类：确定性采样器（如 euler、dpm++ 2m、ddim 这类不吃随机噪声的）步数越多越趋于稳定，存在明确的收敛点，过了就是浪费；而 ancestral / SDE 类（名字里带 a 或 sde）每一步都会注入新的随机噪声，改变 steps 相当于换了一条完全不同的轨迹——对这类采样器谈「多少步收敛」本身没有意义，它压根不收敛到同一张图。

步数 ≠ 前向次数 高阶采样器（如二阶方法）为了让每一步更准，会在一步之内向 U-Net 提交不止一次前向请求。所以 steps=20 对一阶采样器和对二阶采样器，实际算的次数不一样；比较不同采样器谁更「费」，要看的是总前向次数，而不是 steps 这个数字本身。08 节说过 CFG 会让每一步跑两遍（正负提示词各一次）——这个乘数也要算进去。
计算器 总前向次数

再看 denoise。它常被理解成「去噪力度」，但它真正控制的是从哪个噪声水平起步。denoise = 1.0 表示从纯噪声（t 最大处）开始走完整条路径，这是文生图的默认值；小于 1 时，会拿输入的那块 latent加上一部分噪声，只从这个较浅的噪声水平往回走剩下的一段，原图的大结构因此被保留下来——这正是图生图（img2img）的做法，denoise 越小，保留的原图结构越多。

两个常见踩坑 「steps 越多越精细」——见上文，过了收敛点就是白等，尤其在 ancestral 类采样器上，多等的步数换来的只是另一张不同的图，谈不上更精细。
「denoise 是降噪强度，调小图会更干净」——恰恰相反。在纯文生图流程里把 denoise 调小，起点噪声是少了，但留给模型去噪的路径也跟着变短了，一张原本该走完整条路径的图被从半路截断，结果是一张没被去噪完全、发灰发糊的图。denoise 只在图生图这种「有原图打底」的场景里调小才合理。
本节收束 steps 是积分精度，存在收敛点，且收敛点因采样器类型而异；denoise 是起步噪声水平，不是强度旋钮。图已经在潜空间里走完了整条路径，接下来要做的是把 LATENT 变回看得见的像素——12 节讲 VAE 解码，以及「发灰发糊」还有另一个更常见的成因。
[ 12 · 节点 · VAE ]

VAE 解码：潜空间回到像素，以及图为什么会发灰发糊

KSampler 吐出来的还是 LATENT，一堆数字，肉眼看不了。VAE Decode 节点把它变回 IMAGE——这是六个节点里的最后一棒。

VAE 在整条链路上其实出现过两次，很多人把它们混成一件事：04 节讲潜空间压缩时，用的是编码器（像素 → latent），那是图生图和 inpaint 才会走到的路；文生图从 Empty Latent 出发，压根没有原图可编码，全程只用解码器（latent → 像素），也就是本节这一个方向。

解码器在做什么 把 [1, 4, H/8, W/8] 的张量还原成 [1, 3, H, W] 的像素图。它不是把每个数字简单地放大插值，而是一个专门训练出来的上采样网络——要凭 4 个通道里的信息，去「编」出 8×8 倍于原来位置数量的像素细节。

发灰发糊，通常是这两件事之一

VAE 版本不匹配是最常见的头号原因：checkpoint 自带的 VAE 和你外挂加载的 VAE 不是同一个、或者版本对不上，表现为整张图像蒙了一层灰、颜色发淡、对比度不足——就是上面右边那格模拟的样子。VAE 本身的信息损失是另一回事：04 节说过潜空间压缩不是无损的，最容易在这个过程里丢掉的是极细的纹理、小字、密集网格、人眼虹膜这类高频细节——它们在 4 个通道、H/8×W/8 的分辨率里根本没有足够的位置被编码下来。放大出图之后还要单独修脸修手，部分原因就在这里：那些细节从一开始就没被带进 latent。

分辨发灰 vs 焦掉 发灰偏淡、对比度不足，大概率是 VAE 的问题（版本不匹配或信息损失）；颜色过饱和、边缘发硬「烧焦」，大概率是 08 节讲的 CFG 数值给得过高。两者的表现方向正好相反，别混着排查。解码默认是整张一次做完；显存紧张时才会退成分块（tiled）进行，显存紧张时会分块解码来省显存，代价是块与块的接缝处偶尔会看出拼接痕迹——这个只在极端情况下才明显，不是解码器的常态问题。

误区 「VAE 决定画风」——不是。画风由底模的 U-Net 决定，VAE 只负责最后一步的色彩还原与细节重建。换一个 VAE，不会把写实风格变成动漫，顶多是色彩和细节的观感有差别。

参数总表：每个旋钮挂在哪个节点

前面十二节把每个参数出现的位置和原理讲了一遍；这一节反过来，把它们摊平成一张表，方便以后回查。整条流水线上真正需要你决定的参数并不多，而且它们分属不同节点、互不干扰——搞清楚「这个旋钮挂在谁身上」，比记住一个推荐数值更有用。这也是为什么排障最有效的做法不是把参数挨个试一遍，而是先想清楚问题出在哪个节点，再去动挂在那个节点上的参数——第 14 节会把这套方法具体演示一遍。

排障 决策链（点开你看到的症状，可以逐层展开）
整体发灰、颜色偏淡、像蒙了一层

先查：VAE Decode 用的 VAE 是不是和 checkpoint 不匹配——外挂了一个和当前模型不配套的 Load VAE，或者反过来该用外挂却用了不对的内置解码器。VAE 编解码器如果和训练时不是一套，解码出来的颜色范围会整体跑偏，这是发灰最常见的成因。

怎么办：换回 checkpoint 内置的 VAE，或换一个官方标配的 VAE 试一次。

换过 VAE 还是发灰？再查这个

查 KSampler 的 denoise 是不是被调到了 1.0 以下。denoise 决定从哪个噪声水平起步；纯文生图（从 Empty Latent Image 起步）如果 denoise<1.0，前面该走的去噪路径没走完，会直接留下没擦干净的噪声，看起来就是灰蒙蒙的。

怎么办：把 denoise 调回 1.0。

验证：固定 seed，只改这一个参数，对比两张图——发灰消失，说明就是这个原因。

过饱和、边缘发硬、像烧焦

先查：KSampler 的 cfg 是不是偏高。cfg 是「沿正负提示词方向放大多少倍」的倍数，调得越高，对比度和饱和度会一起被放大，边缘变硬，调过头就是局部过曝、烧焦。

怎么办：降 cfg 是第一步，不是加负面提示词——负面提示词解决的是「画面里出现了不想要的东西」，不是「整体力度太猛」这件事。

验证：固定 seed，只降 cfg，对比对比度和饱和度是否回落。

完全不听提示词

先查：KSampler 的 cfg 是不是过低——cfg 太小，等于正负方向的放大倍数太小，等于几乎不做放大——cfg 趋近 1 时合成结果就等于 εcond 本身，提示词的拉力最弱（要再小到 1 以下，才真的开始退向无条件预测）。这时不是模型「不听话」，是你根本没给它施加引导，自然谈不上「听不听话」。

cfg 正常？再查这个

查 CLIP Text Encode 里的 prompt 是不是超过了 75 个内容 token。上下文一共 77 token，首尾各占一个特殊标记，超出 75 的那部分内容根本没有进入模型，等于白写。

怎么办：把最重要的描述挪到前面，删掉后面被截断的部分。

token 数没超？再查这个

查关键词是不是被分词器拆成了碎片。分词不按单词切，罕见词、专有名词、中文词很容易被拆成好几个 token，权重语法（如 (词:1.4)）作用在 token embedding 上，词一旦被拆碎，这股拉力也被摊薄了。

怎么办：换成更常见的同义表达试一次。

验证：固定 seed，把 cfg 上下各挪一档跑三张对比——画面明显跟着变，说明 cfg 这一路是通的、问题在提示词那一侧；三张几乎没差别，说明提示词根本没进模型，直接去数内容 token。

构图总是不对（人物出框、主体偏小）

先查：换一个 seed。整条链唯一的随机性来源，是 KSampler 按 seed 生成的那份初始噪声，构图很大程度上由它决定——调 cfg、调 steps 基本救不回构图，它们改变的是去噪的力度和精细程度，不是初始噪声里已经「埋」下的大致轮廓。

换了几个 seed 都不对？再查这个

查 width／height 是不是远离了底模训练时的原生分辨率。宽高需要是 8 的倍数，离原生分辨率越远，越容易出现出框、多头多肢这类结构性崩坏。

验证：固定其它参数，只换几个不同 seed 对比——构图问题跟着 seed 换，说明本来就是噪声决定的，该调的是 seed，不是 cfg／steps。

图很糊、细节像糊在一起

这个症状有两种常见成因，先用下面的方法区分是哪一种。

情况 A · denoise 没到 1.0

纯文生图（从 Empty Latent Image 起步）如果 denoise<1.0，去噪路径没走完，糊和发灰经常一起出现。先看 denoise 的数值。

情况 B · steps 太少

steps 不够，数值积分还没走到收敛点就被迫收尾，图像结构没画完整。denoise 已经是 1.0 时，多半是这种。

区分方法：先看 denoise 是不是 1.0——不是，先调回 1.0 再看；如果已经是 1.0，固定 seed 只调大 steps，糊感随之减轻说明是步数不足，没变化则要往分辨率或 VAE 上找。

验证：固定 seed，单变量对比调整前后的结果。

细纹理、小字始终糊

这是潜空间这套表示的固有上限：512×512×3 的画面在链路里只有 64×64×4 个数可用，压缩 48 倍，细纹理、小字、密集网格是最先丢的那一批——不是任何采样参数能解决的，不用在 denoise／steps／cfg 上找原因。

怎么办：用更大分辨率生成，或者生成之后接一个放大流程处理。

每次生成结果都不一样，没法对比

先查：KSampler 上的 control_after_generate 是不是没设成 fixed。seed 是唯一的随机性来源，如果每次自动 increment／randomize，别的参数再怎么对齐也对比不了。

已经是 fixed？再查这个

查 KSampler 的 sampler_name 是不是 ancestral／SDE 类。这类采样器每一步都会重新注入噪声，不收敛——就算 seed 固定、steps 不变，结果依然不是唯一确定的。

验证：把 control_after_generate 设成 fixed，且换一个非 ancestral／SDE 的采样器，同样参数跑两次——图应该完全一致。这本身就是「调参前先固定 seed」这条准则最直接的验证。

生成太慢

先查：别急着降分辨率，先算一下 steps × 采样器阶数 × (cfg 开则 ×2) 这个乘积——它才是真正决定前向次数、也就是耗时的东西。分辨率主要影响显存占用，对「跑多少次网络」影响没那么直接。

怎么办：记下当前 steps、所选 sampler_name 的阶数、cfg 是否开启，从这个乘积里最大的那个因子上省。

下面每条「常见说法」单看都不算离谱，只是对了一半，或者把原因归到了错的节点上。第二列说的是原因，不是简单判对错。

常见说法为什么不准确准确的说法
「去噪就是把模糊的图变清晰，像 Photoshop 的降噪滤镜」滤镜是在一张已经存在的图上做平滑，抹掉的是画面里本来就有的噪点；这里是从一团纯随机噪声出发，没有「原图」可抹。从纯噪声出发，一步步减出一张原本不存在的图（见第 03 节）。
「模型预测的是图本身」「干净图长什么样」的分布正是模型要学的全部难点；把目标换成分布已知、均值为 0 的噪声，等于把开放式生成问题转成有固定基准的残差回归，才训得动。网络每一步预测的是噪声 ε，减掉预测值才是去噪（见第 03 节）。
「潜空间就是把图缩小的缩略图」缩略图是像素平均，潜空间是 VAE 学到的语义级压缩；64×64 里每个位置编码的是原图对应 8×8 区块的语义与结构，不是那 64 个像素的颜色平均。潜空间是换了一套表示，不是把图缩小（见第 04 节）。
「CFG 就是提示词权重，比如给某个词加括号加权重」权重语法（如 (word:1.3)）改的是 CLIP 编码阶段的 token embedding，只生效一次；CFG 改的是 KSampler 里每一步怎么合成两路噪声预测，作用的节点和时机完全不同。权重语法与 CFG 是两件不同机制，分别对应第 07 节与第 08 节。
「CFG 越高，模型越听话」CFG 变大不是「更遵循提示词」的开关，而是把 ε_cond − ε_uncond 这个方向放大的倍数；放大到一定程度就会冲出模型训练时见过的分布。CFG 越高是越极端，过饱和、边缘发焦是冲出分布的信号（见第 08 节）。
「负面提示词能把画面里的东西删掉」负面提示词只是改变了 ε_uncond，从而改变了 ε_cond − ε_uncond 这个去噪方向；它影响的是「该往哪个方向走」，不是在已经生成的像素上做减法。负面提示词改变去噪方向，不是删除元素（见第 08 节）。
「提示词写得越长，模型考虑的信息越多」CLIP 的上下文长度固定 77 个 token，首尾各占一个特殊标记，内容只能放 75 个；超出的部分在编码这一步就已经丢失。超过 75 个内容 token 的部分被直接截断，彻底没进模型（见第 07 节）。
「steps 越多，图越精细，一直加没坏处」数值积分存在收敛点，继续加步数只是让轨迹更贴近同一个终点，超过后基本没有可感知的收益；对 ancestral / SDE 类采样器，每步还会重新注入随机噪声，改 steps 等于换了一条新轨迹。有收敛点，超过无收益，某些采样器上甚至会换成另一张图（见第 10、11 节）。
「denoise 是降噪强度，调小图会更干净」denoise 实际控制的是从哪个噪声水平起步；纯文生图本就该从满噪声起步，调小意味着提前跳过了该走的步骤，该擦的噪声没擦完，画面反而发灰发糊。denoise 控制起始噪声水平，不是滤镜式的降噪程度（见第 11 节）。
「seed 是玄学幸运数字」seed 只是初始噪声这一份随机数的起点，构图主要由它决定；换掉采样器、CFG、提示词中的任何一个，同一个 seed 也不再对应「熟悉」的结果。seed 只在其余参数完全不变时才谈得上可复现（见第 09 节）。
「VAE 决定画风」画风来自 Load Checkpoint 里的 MODEL（U-Net）权重；VAE 只负责潜空间与像素之间的编解码，不改变构图与内容。画风由 MODEL 决定，VAE 只管色彩还原与细节重建（见第 06、12 节）。
「换个采样器就能提升画质上限」采样器改变的是同样步数下轨迹逼近收敛点的效率，不改变模型本身能画出什么；画质上限由 MODEL 与 latent 压缩率决定。采样器影响收敛效率，不是画质天花板（见第 10 节）。
「图发灰、过饱和、烧焦都是一回事，随便调一个参数试试」发灰发闷与过饱和烧焦是两类不同症状，对应不同环节：前者多半是 VAE 不匹配或 denoise 起点被误调小；后者多半是 CFG 开得过高。不分症状乱调，容易在错误的旋钮上反复试错。先区分症状再选参数：发灰查 VAE 与 denoise，过饱和查 CFG（见第 11、12、14 节）。

扩展它改的是链上哪一段因此会牵动什么
LoRA在 MODEL 与 CLIP 的权重上叠一层小的修正量，插在 Load Checkpoint 之后改的是「预测噪声」这个动作本身与文本编码，所以它能换画风、加概念；不改采样流程，steps / CFG 的含义不变
ControlNet往 CONDITIONING 这一路再挂一支空间条件（边缘图、深度图、姿态骨架）它补的正是第 09 节那个局限——seed 只能大致左右构图。多了一路条件，也就多了一组该调的强度参数
图生图（img2img）把 Empty Latent 换成 VAE 编码器的输出，并且不从最大噪声起步这就是第 11 节 denoise 的真正主场：它决定保留多少原图结构。第 12 节说的「编码器只在图生图出现」指的就是这里
高清修复 / 放大把整条链跑两遍：第一遍出小图，放大后作为第二遍的起点，第二遍用较小的 denoise它绕开的是第 04 节那个天花板——latent 只有 64×64×4，细节的上限在压缩时就定死了
