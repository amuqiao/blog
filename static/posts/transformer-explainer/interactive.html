[ 01 · 起点 ]

一个句子里的缺口

「猫 追 老鼠，因为 它 饿了」——「它」在第 5 个位置，指的是第 0 个位置的「猫」。要让模型把这层意思写进「它」的表示里，就必须把位置 0 的信息真正搬到位置 5。这不是特例，是几乎所有句子都会遇到的最小情形：长距离依赖。

先把「搬信息」拆成三个能测量的问题，别停在直觉上。信息从位置 j 到位置 i，中间要经过多少次计算——这是路径长度；这些计算能不能同时做完，还是必须一步等一步——这是顺序操作数；序列变长之后，每一层的计算量涨得多快——这是每层代价。下面这张图把同一件事画两遍：直接查表，和沿链条传递，数字上的差距一眼能看到。

橙色描边的位置是发问方「它」，蓝色描边的位置是被找的「猫」；灰色细线是 RNN 必须依次经过的相邻连接。

点「播放 RNN 传递」看效果：信息必须先到位置 4，再到 3、2、1，最后才到 0，每一步都要等上一步算完。这不是实现细节，是结构决定的——RNN 把整句压进一个固定维度 d 的隐状态，每读一个新 token 就对这个隐状态做一次仿射变换加非线性重写。第 0 步的信息要想在第 5 步还能被读出来，要扛住 5 次矩阵与非线性的连乘；这次连乘对应的雅可比矩阵，其奇异值可能大于 1 也可能小于 1，多层复合之后效应会被放大——实践中确实常见早期信息难以恢复，但这不等于「梯度一定消失」这个更强的单向结论，衰减和爆炸都可能发生。

补充「它」到底指谁，真实语言里常常不是非黑即白的——这句话里它也可能被读成指「老鼠」。示意注意力矩阵里，第 5 行分给「猫」的权重是 —，分给「老鼠」的是 ———两个候选都拿到了不可忽略的份额。这提示我们要的机制最好能同时分一点给多个候选，而不是像 RNN 的隐状态那样把历史压成一份「最终裁决」。这为后面的 softmax 加权平均埋下伏笔。

这一节只回答「怎么把 A 位置的信息取到 B 位置」这一件事——生成时怎么解码、训练目标是什么、token 一开始怎么变成向量，都不是这一节要处理的，留给后面的章节。

本节收束三条坐标轴摆上桌面了：路径长度、顺序操作数、每层代价。下一节把 RNN、CNN、Self-Attention 三种取信息方式按这三条轴逐一算一遍账，看 self-attention 到底拿什么换来了「一步到达」。
[ 02 · 取舍 ]

三种取信息方式的代价

上一节立起了三条坐标轴。现在把 RNN、CNN、Self-Attention 摆在同一张表里，看每一种做法在这三条轴上分别要付什么代价——这张表决定了后面为什么选 self-attention 作为主结构。

CNN 每叠一层，感受野扩大 k−1，要连通首尾两个位置需要 ⌈(n−1)/(k−1)⌉ 层，这就是 O(n/k) 的来历；换成 dilated 卷积，堆叠层数可以压到 O(log_k n)，但顺序操作数仍是 O(1)，不受影响。
核心权衡Self-Attention 用 O(n²) 的计算，买到了路径长度 O(1)、顺序深度 O(1)——不管 n 多大，任意两个位置之间只隔一次矩阵乘法，而且这次矩阵乘法里所有位置对可以同时算完，不用排队等前面的结果。后面第 06 节起要打的每一个补丁，都是在为这笔交易的副作用买单。

把每层复杂度里的两个主项单拎出来比一比：attention 的打分与取值花费 n²·d，逐位置的仿射变换（RNN 那一层、FFN 类结构）花费 n·d²。这两个表达式在 n = d 处相等——序列长度远小于 d_model 时，二次项占不到主导；n 明显超过 d 之后，它才会反超。这只是把两个主项拿来做量级比较；把多头拆分、W_O 输出投影、门控 FFN 这些真实系数都算进去后，实际「attention 开始主导」的位置会落在 d_model 的若干倍处，这里不给具体倍数。

误区O(1) 说的是路径长度，不是「计算更少」。同样的 n、d，attention 每层的乘加次数（n²·d）往往比 RNN 那一层（n·d²）更多，它不是更省算力的方案。它赢的地方是这些计算彼此没有依赖，可以一次性摊开、并行算完，不必像 RNN 那样一步一步排队。

这笔交易只在 n 不太大的时候划算。n 一旦涨到几万、几十万，O(n²) 那一项会先把显存和延迟都拖垮——这正是第 15 节要处理的边界。

本节收束选定了 self-attention 之后，下一步要回答的是：这个「O(1) 路径」具体怎么实现——一次查询、一次匹配、一次加权，到底是哪三个矩阵在做这件事。
[ 03 · 第一因 ]

把「查找」变成一次可微运算——这是全文的第一因

上一节留下的问题是「到底哪三个矩阵在做这件事」。答案得从一个更朴素的动作里推出来。本节只做一件事：把 d[q] 这种硬查表，一步步软化成一次可微的加权平均。后面 15 节的每个新零件，都在补这次查表留下的某个漏洞——先吃透这一步，剩下的都顺理成章。

先看一次硬查表

普通代码里最常见的取值动作是 d[q]：给一个 key，精确命中就返回 value，命不中直接抛错。这个动作有两条硬伤——只认「完全相等」，容不下「有点像」；对 q 不可微，没法用梯度告诉它「这次找错了，往哪边调一点」。而「它该对应谁」，语言里从来没有精确匹配可言。

三步，把硬查表软化成一次可微检索

顺着上面两条硬伤各修一处，只需要三步：

  1. 打分代替匹配——不再问「key 是否等于 q」，而是问「key 和 q 有多像」，用点积 score = q·k 给出一个连续的相似度。
  2. softmax 代替非此即彼——把一组分数变成一组和为 1 的权重，分数越高分到的比例越大，但谁都能分到一点。
  3. 加权求和代替直接搬运——用这组权重对 V 做加权平均，谁的权重高，谁的 value 就多搬一点过来。
第一因这就是一次可微的字典查询——全文只有这一个第一因，后面每个零件都是它的补丁。三个角色各司其职：Q 是「我要找什么」，K 是「我能被谁找到」，V 是「找到我之后你拿走什么」。而 softmax 干了两件缺一不可的事：把任意分数压成「这次注意力一共 100% 该怎么分」的比例；同时处处可导——分数变一点，权重就连续地跟着变一点，梯度才传得回去。
回扣第 01 节「它」到底指猫还是老鼠，语言本身就没有精确答案——指代是软的。一次加权平均刚好能让「它」同时给「猫」和「老鼠」各分一点注意力，而不必被迫二选一。机制的软，配的正是问题的软。

为什么打分和取值必须是三份独立投影

反例一 · W_Q = W_K 会强制对称若两者相等，score_ij = q_i·k_j = (x_iW_Q)·(x_jW_Q) = x_iᵀ(W_QW_Qᵀ)x_j。W_QW_Qᵀ 对任意 W_Q 都是对称矩阵，代入上式意味着 score_ij 恒等于 score_ji——「它找猫」的分数被迫和「猫找它」完全相等。但语言里的依赖从来不对称：代词对先行词的依赖远强于反过来。被迫对称的打分函数，从数学结构上就学不出这种不对称。
反例二 · W_V = W_K 会混淆职责若两者相等，一个 token「拿什么特征去被别人找到」和「被找到之后该搬走什么内容」被绑成同一份表示。这两件事没道理是一回事：某个词可能因为紧跟在主语后面而容易被找到（key 的事），它真正携带的语义信息（value 的事）却完全是另一套。拆成两份独立投影，两件事才能分开学。

顺带说清一个常见混淆：self-attention 与 cross-attention 唯一的区别，只在于 Q、K、V 各自来自哪个序列——全部来自同一个序列就是 self-attention；Q 来自当前序列、K 和 V 来自另一个序列（比如编码器输出），就是 cross-attention。查询这个动作没变，变的只是去哪张表里查。

[ 04 · 公式 ]

六步走完一次注意力

上一节把注意力讲成一次「可微的字典查询」：Q 问、K 应、V 拿，softmax 让查表可微分。把这句话拆成六步可执行的矩阵运算，就是下面这一行——也是整篇文章里唯一需要背下来的等式——另外两条（参数量、KV cache）会在第 12、15 节自己推出来，不用背。

Attention(Q, K, V) = softmax( Q Kᵀ / √d_k + M ) V

Q、K、V 都不是凭空给定的——它们是同一份输入 X 经三条独立线性层投影出来的：Q = X W_Q，K = X W_K，V = X W_V。多头版本会把 d_k 换成 d_model / h、并行做 h 份，那是第 08 节的内容；这里先按一个头走一遍，把六步看清楚。

关键 为什么打分用点积 Q·K，而不是把 q、k 拼起来再过一层 MLP（additive / concat attention）？两者表达力相近，但点积能把「每一对位置的打分」折叠成一次矩阵乘法 Q Kᵀ——这正是 GPU 最擅长、可以整批并行的运算；additive attention 要为每一对位置都过一次非线性层，无法压成单次 GEMM，工程上慢得多。省下的那层 MLP，就是这个公式看起来「简陋」的原因。
逐步复原 玩具张量 · 4 个 token「猫 / 追 / 老鼠 / 它」· d_k = 4
常见读图错误 Q Kᵀ 的每一行是「某个位置对全序列的打分」，每一列是「某个位置被全序列打的分」——行看的是「我问了谁」，列看的是「谁在问我」，不是一回事。后面的 softmax 是逐行做的，每行独立归一化；如果把行列读反，「每行加起来等于 1」这个结论也会被理解反。
收束 六步走完：三次投影、一次打分、一次缩放、一次加掩码、一次逐行 softmax、一次加权求和。整条链路里唯一可疑的系数是第 3 步的 1 / √d_k——它不是经验凑出来的，下一节把它推导出来。
[ 05 · 细节 ]

为什么必须除 √d_k

上一节把 1/√d_k 放进了公式，这里补上推导：它不是「经验上除一下更稳」，而是一个有确切出处的量纲修正。

打分的方差正比于 d_k

先说清楚这段推导成立的前提：假设 q、k 的各自的分量相互独立、且 q 与 k 相互独立、均值为 0、方差为 1——这大致是训练初始化那一刻的状态（权重刚随机初始化，输入也接近标准化）。训练过程中参数会学习、分布会漂移，下面的等式不再精确成立，但它解释的是「为什么起手不除，训练一开始就会卡住」。

把 q·k 展开成 Σ q_i k_i（i 从 1 到 d_k）。每一项 q_i k_i 独立同分布，均值 E[q_i]E[k_i] = 0，方差 E[q_i²]E[k_i²] = 1。d_k 项方差可以直接相加：

Var(q·k) = Σ Var(q_i k_i) = d_k　　⇒　　Std(q·k) = √d_k

d_k 越大，打分的天然量纲就越大——这不是模型学出来的性质，是点积这个运算本身的算术性质。

后果落在梯度上，不是数值上

打分幅度一大，softmax 的输出会迅速逼近 one-hot：最大的一项吃掉几乎全部概率，其余趋于 0。问题不在输出本身，而在梯度。softmax 的 Jacobian 是 diag(p) − p pᵀ；当某个 p_i → 1、其余 → 0 时，对角项 p_i(1−p_i) → 0，非对角项 −p_i p_j → 0，整块 Jacobian 趋于零矩阵。链式法则往回传时，这一步会把传给 Q、K 的梯度乘上一个几乎全零的矩阵——训练还没开始就已经走不动。

关键 除以 √d_k 恰好把 Var(q·k) 从 d_k 拉回 1，让打分的幅度不再随 d_k 漂移。这是一次量纲修正：把一个会随维度线性增长的量，除回一个与维度无关的尺度——不是玄学常数。
常见误解 「除 √d_k 是为了防止数值溢出」——不对。溢出问题在 softmax 里减去每行最大值（x − max(x)）就彻底解决了，这与 √d_k 无关。√d_k 真正解决的是上面那条梯度消失的链路，是训练动力学问题，不是数值精度问题。
把推导摆到眼前验证 独立标准正态生成的 q、k，实测标准差应按 √d_k 增长；除以 √d_k 之后应稳定在 1 附近

形式上确实很像——两者都在调分布的尖锐程度，数学上都是「除一个数再 softmax」。但作用的位置和性质不同：1/√d_k 作用在 attention 分数上，由 d_k 唯一确定，是模型结构里定死的量纲修正，训练和推理时都不变；采样温度作用在输出 logits 上，是推理阶段一个可以自由调节的超参数，用来控制生成的随机性。不要把两者混为一谈。

[ 06 · 漏洞① ]

加权平均是置换等变的，顺序丢了

纯粹的加权平均分不清「谁排第几」——把输入的行打乱重排，attend 出来的还是同一堆数，只是换了个编号。这一节先用两行代数把这件事钉死，再拿数据重算一遍验证。

漏洞self-attention 对行序不敏感：只要参与运算的还是同一个多重集合，输出内容一字不差，只是换了行号
→
补丁把「坐第几个」也变成一份输入内容，让顺序变成模型能读到的信号——下一节讲位置编码

把输入按置换 P 重排行得到 PX。Q、K、V 都是 X 的逐行线性变换，故 Q'=PQ，K'=PK，V'=PV——线性变换只认某一行的内容，不认它排第几。于是 scores'=P·scores·Pᵀ；逐行 softmax 保持这个对应，weights'=P·weights·Pᵀ；因此 out'=weights'V'=P·weights·V=P·out（用了 PᵀP=I）。整条推导只用到「P 是行的重排」，跟 W_Q、W_K、W_V 具体是什么无关——前提是 mask 不依赖绝对位置（第 11 节的 causal mask 是故意打破这一点的特例）。

等变，不是不变out'=P·out 说明输出每一行都跟着换了位置——第 i 行装的是原来第 P(i) 行的内容。这叫置换等变（equivariant）。但只追踪某个具体 token（比如「老鼠」），不管它被搬到第几行，算出来的向量都和原来一样。「不变」（invariant）是另一件事——要等到后面接一个跨位置求和 / 平均的池化层、不再区分行号，输出才真正对置换视而不见。

后果很具体：对纯 attention 来说，「猫追老鼠」和「老鼠追猫」是同一个多重集合换了座位表——QKᵀ 的每个元素只看参与运算的那对 token 内容，不看坐第几排。可语序恰恰是语言拿来扛语义的骨架，一个对语序视而不见的机制，没法直接处理语言。

对照 RNN / CNNRNN 把顺序焊在结构里：按 t=1,2,3,… 递归地读，隐状态天然带着「我是第几个」；CNN 焊在卷积核的相对偏移里。代价正是第 02 节算过的账：RNN 路径长度 O(n)、不能并行；CNN 要堆很多层才能撑满感受野。Attention 为了拿到 O(1) 路径长度和逐 token 并行，把这份结构自带的顺序整个扔掉——所以必须把顺序当成普通输入内容，和词义一起塞进 X 里。

[ 07 · 补丁① ]

位置编码：从正弦波到 RoPE

顺序丢了，最直接的补法是给每个位置发一张牌。牌怎么发，从查表到正弦波再到旋转，每一步都在还上一步欠下的账。

承接的漏洞顺序在一次纯注意力里等变地丢失
→
本节的补丁查找表 → 正弦波 → 旋转 q、k 的 RoPE

最直接的想法：给每个位置发一张学出来的座位牌

最省事的做法是建一张位置嵌入表，和 token embedding 按位相加。learned absolute position embedding 训练简单，但表只有 max_position_embeddings 行，训练定多长表就多长——遇到表外位置，外推能力几乎为零。它也是本文唯一「参数量随序列长度增长」的部件（max_position_embeddings × d_model），第 17 节的误区表会再碰到这个例外。

正弦编码：把位置拆成一组不同频率的刻度

原始 Transformer 换了不用学的写法：PE(pos,2i)=sin(pos/10000^(2i/d))，PE(pos,2i+1)=cos(pos/10000^(2i/d))。d 个维度两两一对各配一个频率：i 小频率高，位置一动这维就转一大圈；i 大频率低，要挪很远才有反应——一整把刻度不同的尺子叠在一起，把位置编成一份多尺度指纹。

一个额外性质，别夸大PE(pos+k) 可由 PE(pos) 经一个只依赖 k、不依赖 pos 的线性变换（二维旋转）算出——这只说明模型有机会学会利用相对位置，相对关系仍要模型自己从内容差值里学。

换个问法：模型真正想知道的是「你离我多远」

注意力真正想用的常是「你离我多远」，不是「你排第几」——句法与指代关系大多是相对的。绝对位置向量绕了个弯：先加进各自内容，再指望模型减出差值。把距离直接写进打分，这道弯就省了。

RoPE：不再加位置，而是旋转 q、k

RoPE（Rotary Position Embedding）不把位置向量加到内容上，而是把 q、k 按位置转一个角度：d 维向量两两分组成 d/2 个二维子空间，第 m 个位置在第 i 个子空间里转过角度 m·θ_i，θ_i=base^(−2i/d)，base 即 rope_theta。

要盯住的性质：记角度 m 的旋转矩阵为 R_m，二维旋转满足 R_mᵀR_n=R_{n−m}（先转回 m 再转到 n，等价于直接转 n−m）。于是 ⟨R_m q,R_n k⟩=qᵀR_{n−m} k——点积只依赖 n−m。相对位置就此被直接写进了打分本身，不必先塞进内容再等模型减差值。

两个工程后果：RoPE 只转 q、k，不碰 V；它是逐 token、无参数操作，天然兼容 KV cache——缓存里是各 token 已经旋转好的 K 和未经旋转的 V，新 token 只需转自己的 Q。第 15、16 节会再用到。

长度外推：训练之外的位置怎么办

θ_i 是位置的连续函数，形式上可外推到更长位置，但效果通常明显变差；实践里更常见的是调 base 或对位置索引做缩放（NTK-aware、线性插值、YaRN 一类思路）换取更长窗口——这也是扩上下文时常先动 rope_theta 的原因，具体效果依赖模型与数据，不给结论。

[ 08 · 漏洞② → 补丁② ]

一份预算不够用，所以要多头

一次 softmax 只能产出一组和为 1 的权重——当一个位置同时需要好几种不同的信息时，它必须在这些需求之间做取舍。

漏洞②一次查询只能表达一种关系：「它」要同时找先行词、看谓语、辨从句边界，但一次 attention 只有一组权重。
→
补丁②拆成 h 组并行小查询：各管一种关系，再用 W_O 混合回来。换成第 03 节那本字典的说法：不是去查一本更厚的字典，而是同时摊开 h 本更薄的字典各查一次——每本只管一类关系，查完再由 W_O 把 h 份结论并成一份写回去。

以「猫追老鼠，因为它饿了」为例。「它」这一个位置，同一时刻至少要完成三件互不相关的检索：找到先行词「猫」、确认紧邻的谓语「饿」、判断自己站在从句的哪一侧（「因为」引出的边界）。可是 softmax(QKT/√d_k)V 只算一次——这一行权重加总严格等于 1，多分给「猫」一点，就必须少分给「饿」一点。这不是权重没学好，是加权平均本身的零和结构：一组分数，服务不了三种互不相关的需求。

补丁是把一次预算不够的检索拆成 h 份互不干扰的小检索：并行跑 h 组独立的 W_Q(i), W_K(i), W_V(i)，每组只输出 [n, d_head]；把 h 个结果沿最后一维拼接成 [n, h·d_head]，再过输出投影 W_O 混合回 d_model。每一组都能自由地把权重全押在「先行词」上，不用和别组分摊同一份预算。

关键通常取 d_head = d_model / h——多头不是把表示变宽，而是把同一个 d_model 切成 h 份并行检索。含 W_O 在内总参数量与单头等宽时基本持平，量级都是 4·d_model²（只算权重矩阵，不含 bias 与 Norm）——换来的是 h 个专门化的低维子空间，不是更大的模型。

W_O 不是可选装饰：concat 出来的 h 段彼此互不相通，第 3 段完全不知道第 1 段发生了什么。W_O 是一个 [h·d_head, d_model] 的线性层，负责把各头独立给出的「结论」重新混合成统一表示；少了它，模型看到的只是 h 份互不知情的拼接。h 也不是越大越好——h 越大，d_head 越小，单头能分辨的方向越少；h=1 直接退回预算冲突，所以 h 是「专门化」与「单头容量」的权衡，靠实验定，不是理论最优。

误区
  • 多头不是模型集成：集成是几个完整模型各自答完再平均；这里是同一层内部切成 h 份互补的子空间，且注定要被 W_O 融合——「头」从未作为独立模型存在过。
  • 「每个头都有清晰分工」是可视化之后才看到的印象，不是训练时规定的目标；头与头之间冗余明显，剪掉一部分头性能往往几乎不掉。
  • 头数不改变 O(n²) 量级：h 个头各算一次 n²·d_head，加总仍是 n²·d_model，只是拆成并行。

[ 09 · 漏洞③ → 补丁③ ]

只会混合不会加工，所以要 FFN

attention 只重新分配信息，不替信息做加工——这是下一个必须补的漏洞。

漏洞③只会混合，不会加工：A·V 对 V 是线性的，V 又是 X 的线性投影。
→
补丁③逐位置跑一个两层 MLP：FFN(x)=W₂σ(W₁x+b₁)+b₂，只看自己，负责真正的非线性加工。

给定一组注意力权重 A，输出 A·V 对 V 而言是线性运算——换成别的加权方式也改变不了这一点；V 本身又是 X 的线性投影 W_V。softmax 带来的非线性只发生在算权重 A 那一步，信息在 token 之间流动的方式，从头到尾都是「取一组加权平均」。换句话说：attention 精于重新分配信息，却不对某一个位置的内容做深加工——它没有哪一步会把内容揉碎重组。

补丁是在每个位置上独立跑同一个两层 MLP：FFN(x) = W₂ · σ(W₁x + b₁) + b₂，中间维度 d_ff 通常取 4·d_model。「逐位置」（position-wise）是这里的关键——它完全不看别的 token，所以复杂度是 O(n·d²)，不会像 attention 那样产生新的 n² 项。

这一步有两种互补的理解方式。第一种：升维再降维的非线性加工——先把每个位置的表示投到更宽（d_ff）的空间做非线性筛选，再压回 d_model；attention 负责「从哪里取」，FFN 负责「取来之后怎么理解」。第二种更有意思：key-value memory——W₁ 的每一行像一个 key，检测某种模式，激活值就是匹配度；W₂ 的每一列像对应的 value，决定往输出里写回什么。于是 FFN 也是一次查表，只是查的字典不一样：第 03 节的 attention 查的是「这句话临时组成的字典」——K、V 都来自当前序列，换一句话就换一本字典；FFN 查的是「权重里固化的那本字典」，与输入的具体序列无关。这是一个被广泛使用的解释视角，不是严格意义上的等价证明，但确实是全文最漂亮的呼应之一。

关键单层里 attention 的 W_Q/W_K/W_V/W_O 合计约 4·d_model²；FFN 的 W₁、W₂ 合计约 2·d_model·d_ff。取常见的 d_ff = 4·d_model，FFN 就是 8·d_model²——一个 Transformer block 里，约三分之二的参数在 FFN 里，不在 attention 里。这个「三分之二」有前提：它属于标准 MHA + 两矩阵 FFN + d_ff = 4·d_model 这组经典配置。换成现代常见的 GQA + 门控三矩阵 FFN，FFN 的占比只会更高——具体数字别背，第 16 节的计算器可以让你把自己的 config 填进去当场算。（口径：只算权重矩阵，不含 bias、Norm 参数与 embedding。）

激活函数也在演进：从 ReLU 到 GELU，再到 SwiGLU 这类门控变体——用两个投影相乘做门控，因此需要三个矩阵而不是两个，实现里通常会相应调小 d_ff 以维持总参数量。

呼应第 02 节的账本：attention 混合信息，代价是 n²·d；FFN 加工信息，代价是 n·d²——两种代价、两种分工，互不替代。

收束现在每一层都能「取信息 + 加工信息」了。但要把这样的层堆到几十层，训练会直接崩——下一个漏洞是优化问题，不是表达能力问题。
[ 10 · 漏洞④ → 补丁④ ]

要堆几十层，先让梯度过得去

前九节讲完了一层内部的事：怎么查、查多份、查完怎么加工。但真实模型从不只用一层——表达能力主要来自深度，能堆几十层的前提，是层间信号和梯度不能失控。

漏洞④一层能取信息、能加工信息，但一层不够，真实模型要堆几十层；纯堆叠时正向信号尺度逐层漂移，反向梯度经过一长串 Jacobian 连乘后消失或爆炸。
→
补丁④残差连接 x + Sublayer(x)，外加 LayerNorm / RMSNorm 稳住尺度。

把很多层直接首尾相连，看着自然，实际会出两个问题。正向看，表示的整体尺度每经过一层都可能被放大或压缩一点，几十层累积下来早已不在一个量级。反向看，误差信号要从最后一层传回第一层，相当于几十个 Jacobian 连乘——只要每个乘子的谱半径略大于或略小于 1，结果就会指数级放大或缩小，这正是深层网络梯度消失、爆炸的来源。

残差连接给出的解法很朴素：不让每一层重写表示，而是只学一个增量：x ← x + Sublayer(x)。这一个加号改变了求导结构：∂(x + f(x)) / ∂x = I + ∂f/∂x。式子里那个恒等矩阵 I 是关键——不管 Sublayer 学到的雅可比多小，梯度都至少能沿着这条恒等路径原样传回去，不会因为连乘而彻底消失。

心智模型把整份表示想成一条贯穿全网的公共总线——残差流（residual stream）：每个 attention 子层、每个 FFN 子层都只做同一件事——从总线读一份当前的 x，算出一个增量，再加回总线。理解「信息如何跨层累积」，靠的是这条总线，不是某一层单独做了什么。

光有残差流还不够——增量不断叠加，总线的数值分布仍会跑偏，得有人定期拉回可控范围，这就是 Norm 的角色。LayerNorm 对每个 token 自己的特征维度做归一化：算出该 token 自己的均值、标准差，减、除，再乘可学缩放 γ、加偏移 β——全程不看 batch 里的其他样本，也不看同序列里的其他 token。

方法统计范围依赖 batch 大小？变长序列 / 自回归解码
BatchNorm同一特征，沿整个 batch 统计均值方差依赖差——不同样本当前有效长度不同，统计量对不上
LayerNorm单个 token 自己的全部特征维度不依赖天然适配，与 batch 大小、序列长度无关
RMSNorm单个 token 自己的特征维度，只算均方根、不减均值不依赖天然适配，且少一次统计、少一个偏移参数

这是一个「约束决定选型」的例子：变长序列、逐 token 自回归解码这些约束，直接淘汰了依赖 batch 统计的 BatchNorm，留下与 batch、长度都无关的 LayerNorm。RMSNorm 更进一步，用 x / sqrt(mean(x²) + ε) · γ 省掉减均值这一步，效果相近，因此在现代大模型里很常见。

Post-LN 还是 Pre-LN：Norm 放哪里，决定残差流干不干净

残差解决了「有没有恒等路径」，Norm 放的位置还有讲究。原始 Transformer 用 Post-LN：x ← LayerNorm(x + Sublayer(x))——归一化在相加之后，恰好套在刚建立起来的残差通路上，纯净的恒等路径又被 Norm 包了一层；层数一深，训练对 warmup 就很敏感，容易训不稳。现代主流是 Pre-LN：x ← x + Sublayer(LayerNorm(x))——把 Norm 挪进子层内部，只归一化喂给子层看的那份拷贝，主干加法保持干净，训练稳定性明显更好。

交互 · 切换排列方式，看 Norm 方块挪到哪、主干（残差流）是否被打断

Pre-LN 不是没有代价。主干只做加法、从不被重新归一，残差流的数值范数会随层数持续累积、整体呈增长趋势——层数越多，总线上的数值就越大。所以 Pre-LN 模型在整个 stack 的最后通常要再补一次 final norm，把送进输出投影前的表示尺度重新拉回可控范围；少了这一步，最后一层的分布会和初期完全不在一个量级。

[ 11 · 漏洞⑤ → 补丁⑤ ]

不能看未来，也不能看 padding

残差和 Norm 解决了「能不能训得动」，但注意力还有一个默认设置没处理：softmax(QKᵀ/√d_k) 默认让每个位置对整个序列开放，谁都能看谁。这个默认值在两种常见场景下是直接错的。

漏洞⑤加权平均默认对全序列开放：自回归生成时会看到未来、拼 batch 时会看到无意义的 padding。
→
补丁⑤在 softmax 之前，把不该看的位置的分数加上 −∞。

第一种是自回归生成：预测第 i 个 token 时，如果它能看到第 i+1 个，训练目标就被泄漏了——模型学到的是「抄下一个词」而不是「预测下一个词」，训练时能抄、真正生成时没有未来可抄，两种行为对不上。第二种是变长 batch 里的 padding：为了把长短不一的句子拼成同一个矩阵，短句子后面要补几个没有语义的 <pad> 位置；如果这些位置也参与加权平均，就会把无意义的向量混进真实 token 的表示里。

为什么是 softmax 之前的 −∞两种情况的补丁是同一个动作，但有个容易被忽略的实现细节：为什么一定要在 softmax 之前动手，而不是算完权重之后把不该看的权重清零？因为 softmax 保证每一行的权重加起来等于 1；先算权重再清零几个，剩下的权重加起来就不到 1，等于凭空缩小了这一行能拿到的信息总量。而在 softmax 之前把分数设成 −∞，exp(−∞) = 0，归一化会自动只在剩下的可见位置之间重新分配，行和依然精确等于 1。实现里通常用一个足够大的负数（如 −1e9，或该 dtype 能表示的最小值）去近似 −∞。

[ 12 · 组装 ]

一个 Transformer Block 的完整数据流

把 03～11 节的五个漏洞的补丁按顺序装回去，就是一个标准 Pre-LN decoder block（下面零件表把「残差」与「Norm」分两行列，是因为二者代价不同，但它们同属补丁④）：数据从残差流出发，被两次「抽出来加工、再加回去」的操作打断，中间穿插的正是前面每一节要修的那个漏洞。

一个 block 只做两件事：把注意力当成一次检索完整跑一遍，把检索结果当成一次加工完整跑一遍；两次都读同一条主线（残差流），改动都以「加」的方式写回去，而不是替换。下面这三行就是完整的账：

x                        [B, n, d_model]
h = x + MHA(LN(x))       LN → Q,K,V 投影 → 分头 [B, h, n, d_head] → attention → 合头 → W_O
y = h + FFN(LN(h))       LN → W_1 升到 d_ff → 激活 → W_2 降回 d_model

拼好一个 block 之后，剩下的深度只是把它重复堆叠。这里有一点值得说，但要说得保守：第一层的注意力只能基于原始 embedding 做检索，Q、K、V 都直接来自输入表示；第二层的注意力查询的，已经是「被上一层读过一遍上下文」之后的表示。检索这个动作本身没有变复杂，变化的是每一层可用的检索材料——这为多层堆叠具备可组合、多跳的检索提供了结构上的条件。至于模型是否、以及如何真的利用这个条件去完成多步推理，属于可解释性研究里仍在打开的问题，这里不下结论。

本节收束一个 block 装好了，往上堆几层是自由的。但还有两个开关没拧：谁能看见谁（mask 的形状），以及 Q 和 K、V 是不是来自同一段序列。这两个开关的组合，就是三类模型的全部差别。
[ 13 · 拓扑 ]

同一个 Block，三种摆法，三类任务

拓扑不是三个不同的模型，是同一个 block 在两个开关上的三种组合：谁能看见谁，以及 Q 与 K、V 是否来自同一段序列。

决定拓扑的其实只有两件事：mask 定的可见性形状（全通、下三角，或分成两段各自的形状），以及 Q、K、V 来自哪个序列（自己查自己，还是查另一段已读完的序列）。选定这两个开关，拓扑就唯一确定了。

双向 self-attention

mask 全通，Q、K、V 都来自同一段输入，每个位置能看到全序列两侧，适合「给一段完整输入、要一个理解结果」的任务：分类、抽取、序列标注、检索式表示。它不能直接做生成：预测某个位置时这个位置本身（以及右边）已经可见，与自回归「只能用已生成部分预测下一个」直接冲突；配套的训练目标（遮住部分位置、靠双向上下文去猜）本身也不是能自回归展开的目标。

Causal self-attention

mask 是下三角，Q、K、V 仍来自同一段序列，但每个位置只能看到自己和左边。这个约束换来关键优势：一次前向里每一个前缀都同时完成一次「预测下一个 token」，训练信号是逐位置的，而不是整段只给一次监督；推理时每个位置只依赖左边已算过的 K、V，可以缓存下来做增量解码（原理见 15 节）。

Encoder 双向 + Decoder causal + cross-attention

encoder 全通 mask 双向读完输入；decoder 下三角 mask 自回归生成；两者之间再插一次 cross-attention——Q 来自 decoder 正在写的这一句，K、V 来自 encoder 读完输入后的输出。这是第一因（03 节）的直接复用：查询动作没变，字典来源从「自己这段」换成「另一段已读完的」。适合翻译、摘要一类边界清晰的转换任务；代价是两套参数加一次 cross-attention 开销。

为什么现在 decoder-only 是主流

下面几条属于领域内的共识性解释，没有单篇论文能一次性证明，措辞上用「主要原因通常归结为」而不是定理：

  1. 一个因果语言建模目标几乎能吃下任何形态的原始文本；把「输入」「输出」看成同一条序列的前后两段，encoder-decoder 能做的事用 prompt 拼接就能表达。
  2. 训练信号密度更高：逐位置预测，同一段文本里每个位置都是一次独立监督，而不是整段只对应一次标签。
  3. 工程上只有一种注意力形态、一种 mask，KV cache 与批处理都更简单；规模化时统一实现比结构巧思更值钱。

但这不是说双向表示「被证明更差」——输入需要反复双向消化的任务上它仍有优势；更准确的说法是「统一目标 + 规模化」的收益压过了结构专门化，这是工程权衡，不是机制必然。

O(n²) 的账，以及工程怎么还

  
第 02 节说过：attention 用 O(n²) 的计算换 O(1) 的路径长度。这笔交易到底怎么记账、账单又摊在训练和推理的哪个环节，是这一节要说清楚的事——计算和访存是两本完全不同的账，等到了推理阶段，代价还会悄悄换个地方。


  
第一笔账：算力

  
一次 attention 里，QKᵀ 把 [n,d] 的 Q 和 [d,n] 的 Kᵀ 相乘得到 [n,n] 的分数矩阵，AV 再把 [n,n] 的权重和 [n,d] 的 V 相乘还原成 [n,d]，两步都是 O(n²·d)。而 Q/K/V/O 四个投影与 FFN 是逐位置的矩阵乘法，每个位置各自算一份 O(d²)，n 个位置合起来是 O(n·d²)——这正是第 02 节留下的 n²·d 与 n·d² 两个主项。

  
序列长度翻倍，n²·d 项翻四倍，n·d² 项只翻一倍：这就是为什么长文本任务里最先变贵的永远是 attention 本身，而不是 FFN。多头本身不改变这个阶——d 是把预算切成 h 份之后每个头的维度，h 份 n²·(d/h) 加起来还是 n²·d，头数只改变常数。把系数也算进去：QKᵀ 和 AV 两次矩阵乘法系数是 2，逐位置的四个投影加两层 FFN 在经典设置下系数约是 12（第 12 节的 12·d_model²）。系数不同，两条曲线真正的交叉点就不在恰好 n = d_model 处，而是在 n ≈ 6·d_model 附近——具体倍数取决于头数、FFN 展开倍率等实现细节，下面的图里可以直接调出来看。

第二笔账：显存与访存

  
朴素实现要把分数矩阵完整地摆在显存里，形状是 [B, h, n, n]——注意这里有 h：每个头分别存一份 n×n，头数越多，这块显存越大，即便它不改变 FLOPs 的阶。这个中间张量本该只用一次就丢弃，但朴素写法会先把它整个物化出来，大小随 n 二次增长——n 翻倍，这块显存翻四倍。当 n 涨到几万甚至十几万，它常常比模型权重本身还大：长上下文训练最先炸的显存，往往不是参数或梯度，而是这块从没打算长期存在的中间结果。

  
FlashAttention 的思路是不让这块 [n,n] 矩阵完整存在：把 Q、K、V 按块切开，每次只把一小块搬进片上 SRAM，用 online softmax——每处理一个新的 K/V 块，就用当前块内的最大值增量修正之前维护的最大值和归一化分母——在分块之间滚动更新最终结果。全程只写回 [n,d] 大小的输出，从没有哪一步需要把完整的 n×n 分数矩阵摆在显存里。

  
常见误解FlashAttention 不是近似算法，也没有把 attention 的计算复杂度从 O(n²) 降下来——它算的还是同一套精确的 softmax(QKᵀ/√d)V，n²·d 这个量级纹丝不动。它省的是显存和访存：不再把 [n,n] 写回显存、也不用二次读回来做 softmax 和加权。副作用是 causal mask 里整块都被屏蔽的部分可以直接跳过运算，这才是上面理论上那一半真正被省下来的地方。


  
第三笔账：推理时的 KV cache

  
训练和推理共享同一套矩阵乘法，但推理本身要再拆成两个阶段。prefill 一次性把整段 prompt 的 n 个位置铺开算，矩阵乘法维度都很大，是计算密集的，GPU 算力利用率高；decode 每一步只生成一个新 token，这个新位置的 q 要去和前面已经算完的所有位置的 k、v 做注意力。如果每一步都把前面全部位置的 K、V 重新算一遍，就是把同一份计算在 n 步里反复做了 n 次，退化成 O(n²) 的重复劳动。

  
这不是可选的优化技巧causal mask 保证了一件事：位置 i 的 k、v 只由位置 i 自己和它之前的输入决定，一旦算出来就不会再因为后面新增的 token 而改变。正因为已生成位置永远看不到未来，它们的 K、V 才永远不变，也才可以被缓存——KV cache 是自回归 + causal mask 的直接推论，不是一个额外加上去的技巧。把每层每个 kv head 的 k、v 存进显存，之后每一步只算新 token 那一份、追加进去，decode 阶段单步 attention 的计算量就从「重算全部历史」的 O(n²) 压到了「只对新增一份和 n 个缓存做点积」的 O(n·d)。

  
代价没有消失，只是换了地方：算力省下来了，显存和访存带宽变成新的瓶颈。KV cache 的大小是

  
bytes = 2 (K 和 V)
      × n_layers × n_kv_heads × d_head
      × n × batch × dtype_bytes        ← n 是当前实际序列长度

  
它随实际序列长度 n 线性增长、随 batch 线性增长——这是两个独立的自由度，服务端配置资源时要分别算。由此能解释两个真实的工程现象：

  

    
现象一 · decode 是 memory-bound生成一个 token，要把全部权重和整份 KV cache 从显存读一遍，而这一步真正做的乘加很少——大部分时间花在把数据从显存搬到计算单元上，不是在算。所以单条请求的生成速度主要由显存带宽决定，堆更多算力对它帮助有限。

    
现象二 · batch 提吞吐不提延迟权重只需要从显存读一遍就能同时服务整个 batch，算术强度随 batch 上升，GPU 利用率也随之上去；但每条请求自己的 KV cache 还是要各读各的，一份都不能少，所以 batch 越大，KV cache 越快把显存吃满——这正是长上下文服务里吞吐和显存的核心矛盾。

  

  
GQA（grouped-query attention）和它的极端形式 MQA，做的事是让多个 query head 共享同一组 K、V head：n_kv_heads 从等于 n_heads（标准多头 MHA）降到一个小得多的数，MQA 甚至降到 1。KV cache 只正比于 n_kv_heads，和 n_heads 本身无关——这正是 GQA 只改 W_K、W_V 两个投影的形状、不动 W_Q 和 W_O，就能把 KV cache 按 n_heads / n_kv_heads 成比例缩小的原因，也是现代模型 config 里 num_key_value_heads 这个字段存在的理由。代价是每组内多个 query head 被迫共享同一份 key/value 表达，表达力比标准 MHA 略降，但在实践中被普遍认为很划算。注意别读反一件事：GQA 缩小的是 KV cache 的体积和随之而来的访存量，query head 的数量一个没少，注意力本身的计算量也基本没变——它还的是访存那笔账，不是计算那笔账。

参数量怎么推出来

  
每层 attention 有四个矩阵：W_Q 把 d_model 维输入投成 d_model 维 query，是 d_model×d_model；GQA 下 W_K、W_V 只需要投成 n_kv_heads×d_head 维，各是 d_model×(n_kv_heads×d_head)，两个加起来再乘 2；W_O 把多头拼回来的结果再投一次 d_model×d_model。合计 d_model² + 2·d_model·(n_kv_heads·d_head) + d_model²。当 n_kv_heads = n_heads（标准 MHA）时，n_kv_heads·d_head 就等于 d_model，这一项退化成更熟悉的形式。

十一条误区对照

  

  

    
      
常见说法为什么不准确准确的说法

    
    
      

        attention 就是在算词向量之间的语义相似度，越像的词注意力越大
        Q 与 K 是两套独立学出来的投影（W_Q ≠ W_K），q·k 度量的是「我要找什么」和「我能被谁找到」之间的匹配度，不是同一空间里的相似度；这也是为什么注意力矩阵一般不对称——「猫」看「它」的强度和「它」看「猫」的强度并不相等。见第 03 节。
        注意力打的是「查询—索引」匹配分，不是语义相似度；只有 W_Q = W_K 时打分矩阵才会被强制对称。
      

      

        多头注意力相当于把好几个模型的结果做集成 / 投票
        集成需要每个子模型各自输出一份完整答案再汇总，参数量随子模型数线性增长；多头是把同一个 d_model 切成 h 份子空间（d_head = d_model/h），各自算一次注意力后由 W_O 融合，总参数量约 4·d_model²，基本不随头数变化。见第 08 节。
        多头是「分工的切分」，不是「结果的集成」。
      

      

        位置编码就是告诉模型这是第几个词
        这对 learned 绝对位置编码和 sinusoidal 大致成立，但 RoPE 编码的是查询位置与被查位置之间的相对差 m − n，不是某个绝对序号；ALiBi 根本不改 q/k，而是直接在打分上叠加一个与距离成正比的负偏置。见第 07 节。
        三类方案作用的位置（输入端 / Q、K / 打分）与编码的内容（绝对序号 / 相对差 / 距离偏置）都不同，不能一概而论。
      

      

        self-attention 的参数量会随序列长度 n 增长
        W_Q/W_K/W_V/W_O 都只和 d_model 有关，与 n 无关；随 n 增长的是计算量（O(n²·d)）和显存。但有一个真实例外：learned 绝对位置编码是一张 max_position_embeddings × d_model 的查找表，参数量确实随支持的最大长度线性增长。见第 04、07 节。
        参数量与 n 无关；例外是 learned 绝对位置编码，它的参数量正比于 max_position_embeddings。
      

      

        除以 √d_k 是为了防止数值溢出
        数值溢出（exp 爆炸）靠 softmax 减去逐行最大值就解决了，和是否除 √d_k 无关。真正要修的是：初始化近似下 Var(q·k) = d_k，d_k 越大打分方差越大，softmax 越饱和，Jacobian diag(p) − ppᵀ 趋近于零，梯度消失。见第 05 节。
        √d_k 缩放修的是梯度消失，不是数值溢出。
      

      

        FlashAttention 把 attention 的复杂度降低了
        FlashAttention 是精确算法（不做近似），计算量的量级仍是 O(n²·d)；它优化的是访存模式——用分块和重计算避免把 n×n 的中间矩阵物化到显存里，省的是显存和带宽，不是复杂度。见第 15 节。
        它降低的是显存占用与访存次数，不是复杂度量级。
      

      

        causal mask 能让计算量减半
        朴素实现里 QKᵀ 依旧先把完整的 n×n 分数矩阵算出来，再在 softmax 前对未来位置加 −∞；这一步不会少算任何一个点积。真正能省下计算的是 kernel 级别专门跳过被屏蔽块的实现。见第 11 节。
        causal mask 本身不省计算，要省得靠专门的 kernel。
      

      

        KV cache 是一个可选的性能优化
        KV cache 是 causal mask 结构的直接推论——已经生成的位置，它的 K、V 在后续每一步里永远不变，重新计算纯属浪费；对自回归解码来说它是默认前提而不是可选项，代价是把瓶颈从算力转移到了显存带宽（decode 是 memory-bound）。见第 15 节。
        它是自回归推理绕不开的默认设计，只是把开销从「算力」挪到了「显存带宽」。
      

      

        Transformer 没有卷积 / 循环那样的归纳偏置，所以能力天然更强
        更弱的结构先验意味着模型更依赖数据量和规模去「学出」这些先验；在数据不够多的场景下，带先验的结构（比如局部性、平移不变性）反而常常表现更好。这是一种取舍，不是单方面的优劣。
        弱归纳偏置＝更依赖规模，不等于「更强」。
      

      

        Pre-LN 只是把 LayerNorm 从残差之后挪到了残差之前，纯粹是写法问题
        这个位置变化直接决定了残差流是否保持一条纯加法的恒等通路：Pre-LN 下主干是 x + f(LN(x))，梯度可以绕过 f 直接传回去，这对深堆叠的训练稳定性影响很大；代价是范数会随层数累积，所以模型末尾要补一个 final norm。见第 10 节。
        位置变化改变了残差通路的性质，不是等价写法。
      

      

        把 batch size 调大能让生成（decode）变快
        提高的是总吞吐（单位时间处理的 token 数），单条请求的延迟基本不变，因为 decode 阶段是 memory-bound——瓶颈在于把权重和每条请求各自的 KV cache 从显存搬进计算单元，batch 变大并不会让某一条请求要读的数据变少。见第 15 节。
        batch 提升的是吞吐，不是单条延迟。

    主线
    注意力的第一因是一次可微的字典查询：Q 是我要找什么，K 是我能被谁找到，V 是找到之后拿走什么，softmax 把「硬查表」变成「可微的加权平均」。这一个动作天生带着五个漏洞：顺序丢了、一份 softmax 预算不够、只混合不加工、深堆叠训不动、可见性会失控。位置编码、多头、FFN、残差+Norm、mask 分别是这五个漏洞对应的补丁，组装起来就是一个 Pre-LN block；把 block 堆 n_layers 层、配上合适的可见性拓扑（encoder / decoder / cross），就是完整模型。这一切换来的是 O(1) 的路径长度，代价是每层 O(n²·d) 的计算和随 n 线性增长的 KV cache 显存——这条 O(n²) 的账，就是长上下文会变贵的根源。

        learned：max_position_embeddings · d_model；sinusoidal / RoPE / ALiBi：0
        O(n·d_model)（逐位置相加或旋转，量级远小于 attention 本身）
      

      

        一次 softmax 只有一份和为 1 的预算，多种关系（指代、句法、位置）会互相争抢同一份权重
        多头：W_Q, W_K, W_V, W_O，切分而非变宽
        约 4·d_model²
        O(n²·d_model)（QKᵀ 与 A·V 两步的主项）
      

      

        A·V 对 V 是线性的，softmax 的非线性只用在算权重这一步，token 间的流动方式始终是加权平均，没有逐位置的「加工」
        逐位置 FFN
        约 8·d_model²（d_ff ≈ 4·d_model 时）
        O(n·d_model·d_ff)，量级上等价于 O(n·d_model²)
      

      

        逐层堆叠非恒等映射，梯度在深层网络里衰减或爆炸，训不动
        残差连接 + LayerNorm / RMSNorm（Pre-LN，末尾补 final norm）
        Norm 本身每层约 2·d_model（相对 attention/FFN 可忽略），残差连接 0 参数
        O(n·d_model)（逐元素相加、逐 token 统计，量级很小）
      

      

        不该被看到的位置发生信息泄漏；若在 softmax 之后才屏蔽，行和不再为 1
        causal mask / padding mask（softmax 前加 −∞）
        0
        不改变 O(n²) 这一步本身的量级，但决定了推理时哪些位置需要真正计算与缓存
      

    
  

  

  
口径：参数量只算权重矩阵本身，不含 bias、Norm 的 scale/shift、embedding 表；计算量只给主项量级，忽略常数因子。


  
符号与量级速查

  

  

    
      
符号含义典型量级影响开销的方式

    
    
      
n运行时实际序列长度（prefill 已输入 + 已生成）数百 ～ 数十万平方影响 QKᵀ 与 A·V 这两步的计算与显存；线性影响 KV cache 总量与所有逐位置项

      
d_model隐藏维度 / 模型宽度512 ～ 8192平方影响 attention 与 FFN 的参数量（d_model²）

      
h注意力头数8 ～ 128只做切分，不直接进复杂度量级：d_head = d_model/h

      
d_head单头维度64 ～ 128决定单头点积的方差尺度，是 √d_k 缩放的对象之一

      
d_kquery/key 维度（常等于 d_head）64 ～ 128决定缩放因子 1/√d_k，越大越需要缩放来防止 softmax 饱和

      
d_ffFFN 隐藏层维度约 4·d_model，即 2048 ～ 32768线性影响 FFN 参数量与计算量

      
n_layersblock 堆叠层数12 ～ 100+线性放大单层参数量与计算量的总量

      
n_kv_headsGQA/MQA 里 K、V 的头数，≤ h1 ～ h线性决定 KV cache 大小，与 n_heads 无关

      
Bbatch size（推理时并发请求数）1 ～ 数百线性放大 KV cache 总显存与总吞吐，不降低单条延迟

      
contextconfig 里预分配的最大长度（上界，不是实际长度）2k ～ 1M决定 KV cache 预分配上界；与 n 是两回事——n 是这一刻真正用到的长度，context 是允许用到的长度上限

    
  

  


  

    
三条核心公式

    
Attention(Q, K, V) = softmax( QKᵀ/√d_k + M ) · V

单层参数量 (仅权重矩阵，不含 bias / Norm / embedding)
  ≈ 4·d_model²   [ W_Q, W_K, W_V, W_O ]
  + 8·d_model²   [ FFN 两层，d_ff ≈ 4·d_model ]
  = 12·d_model²

KV cache 显存 (字节)
  = 2 · n_layers · n_kv_heads · d_head · n · B · dtype_bytes
    ↑ K 和 V 两份     ↑ 按 n_kv_heads 计，与 n_heads 无关     ↑ 实际长度 n，不是 context 上界
